1 · Mac and membership

  1. Enroll in the Apple Developer Program with the Apple Account that will own DayBuoy. Complete Apple's enrollment and identity steps.
  2. Install the latest stable Xcode compatible with your Mac, open it, and install requested components. It must include iOS 26 SDK or later. DayBuoy itself targets iOS 26 for WebGPU. Check Mac compatibility and upload requirements.
  3. Xcode → Settings → Accounts → add the enrolled account. Confirm the paid Team appears.
  4. Install Node.js 24 LTS (22.13+ supported). Open Terminal and run:
git clone --branch wip/tidewater-verdict-first https://github.com/jcarroll44/ocean.git daybuoy
cd daybuoy

Use a full clone: checks compare historical commits. Preserve existing local edits before updating an older checkout. Never push to ocean/main.

6 · WeatherKit and shared server

  1. Apple Developer → Identifiers → + → Services IDs: create the WeatherKit ID above and enable WeatherKit as prompted. Keys → + → WeatherKit → register/download .p8. Keep Key ID and Team ID. Follow Apple's setup.
  2. Configure the four WeatherKit values below in the forecast host's encrypted runtime settings. Private .p8 contents are server-only, never native configuration. The server signs short-lived ES256 requests.
  3. Deploy the forecast-only Worker using the included server/forecast-worker.js and D1 migration. Use a data origin reachable without ChatGPT login. Do not publish the development results Worker or its secret. The private review Site already has its own hourly cache.
  4. At commercial launch obtain an Open-Meteo commercial marine key and set OPEN_METEO_API_KEY on the server. Empty uses the non-commercial endpoint; configured selects the customer marine endpoint at the next hourly refresh, without an app rebuild. Check licensing/pricing.
  5. Open https://YOUR-DATA-HOST/api/forecast?beach=inlet-beach without signing in. Require JSON schema 3, source live and feedStatus.weatherKit = active. Compare temperatures, rain, wind and UV at the same location/time before approving WeatherKit quality.

Demand-driven cache: one batch per beach per UTC hour, shared by all users. Each batch has 22 weather points, about 16,400 WeatherKit calls per continuously active beach per 31-day month, within Apple's 500,000 included monthly calls. There is no idle-beach cron or per-user provider polling. NOAA tides, NDBC and NWS surf remain free. Last-known data are marked saved and rejected after 24 hours.

Hourly cloud layers/upper-air wind are derived est. from total cover and surface wind; radiation/CAPE remain unavailable. NWS currently supplies general weather because Apple credentials are absent; NWS may lack UV. Missing sources never invent readings. Apple attribution and source links must remain visible. Original weather readings stay in the free Forecast data view; Plus adds the animated week and native features. Review current WeatherKit terms/attribution before launch; this is not a legal-compliance certification.

7 · Free Sentry and notifications

  1. Create a Sentry Capacitor project on the free Developer tier, with no pay-as-you-go budget. Copy its public Client DSN (not an auth token) into section 8. Blank disables diagnostics.
  2. Retain errors-only settings: no replay, traces, logs, user breadcrumbs or default PII. Enable IP scrubbing and watch your account's actual quota.
  3. No Capgo account, OTA channel or paid push service is used. Updates use TestFlight/App Store. Morning notifications are seven one-off local forecasts from the latest download, refreshed when the app opens, limited by known subscription expiry. They are not freshly fetched background weather; each states its source/update time.

Forecast-only hosting recipe

The existing private Site is already deployed for review. For the native beta, this independent recipe uses your own Cloudflare account and contains no results uploader. Start with its available included quotas, inspect CPU/request/D1 usage in the dashboard, and do not enable a paid plan without reviewing its price.

  1. Create/sign in to Cloudflare, enable Workers & Pages. From the repository root run:
npm exec --yes --package=wrangler@4.92.0 -- wrangler login
npm exec --yes --package=wrangler@4.92.0 -- wrangler d1 create daybuoy-forecast
cp server/wrangler.example.json server/wrangler.local.json

Open the local JSON in a text editor. Replace only REPLACE_WITH_CREATED_DATABASE_ID with the returned D1 UUID. The file is Git-ignored. Then run:

npm exec --yes --package=wrangler@4.92.0 -- wrangler d1 execute daybuoy-forecast --remote --file hosting/drizzle/0000_heavy_doctor_doom.sql --config server/wrangler.local.json
npm exec --yes --package=wrangler@4.92.0 -- wrangler deploy --config server/wrangler.local.json

Set each server variable using wrangler secret put VARIABLE_NAME --config server/wrangler.local.json via the same npm exec prefix, or Cloudflare Worker → Settings → Variables and Secrets. Use the encrypted dashboard field for the multiline WeatherKit .p8. Deploy changed secrets if prompted. Copy the returned HTTPS workers.dev origin into the native configure prompt. Test the JSON endpoint without logging in, check provider flags, and inspect Worker logs for CPU limits. This recipe is not a deployment that was performed in this session.
